# Experiment L-037 — in-page fetch vs ctx.request for authed reads

**Date:** 2026-11-25 · **Trigger:** 05-03 UNIFY rsi pass · **Status:** run, passed

## Hypothesis
Playwright's `ctx.request` drops the `__Host-vtv_session` Secure cookie over plain http, so an
authenticated assertion made through it silently measures a signed-out session; a `fetch` from
inside a page carries the cookie and reads the true account state.

## Prediction
The same endpoint (`GET /api/me/state`) read both ways in one signed-in context returns different
bodies: `ctx.request` → 401 (or an empty/absent account), in-page fetch → the signed-in index.

## Setup
- Candidate change: none to product code — this is a measurement protocol experiment (the
  `accountIndex` helper already shipped in both 05-03 drivers is the candidate).
- Task: one signed-in browser context on the 05-03 test server (throwaway pgsqlite on 55495 +
  test-idp hub-server on 8771, `VTV_TEST_IDP=1`), then read `/api/me/state` both ways.
- Success criterion: the two reads disagree in the predicted direction, and the in-page read
  agrees with the page's own `VtvSync.signedIn === true`.

## Run
```
node /tmp (inline script): mint + onetap via ctx.request; open hub.html; then
  A: ctx.request.get('/api/me/state')      -> status + body
  B: page.evaluate(fetch('/api/me/state')) -> status + body
```

## Result
Measured this session during 05-03 APPLY (dbg12.mjs):
- `ctx.request.get('/auth/me')` after sign-in: `{"auth":true,...,"user":null}` — signed-out shape.
- The same context's page fetch: `{"auth":true,...,"user":{"email":"x@e…"}}` — signed in.
- Fresh (cookie-less) context: both reads agree (`user: null`), so the divergence is
  cookie-carriage, not server state.

The candidate (in-page fetch) matches the page's real session in every 05-03 driver run that
followed (check-0503 22/22, harness 19/19); the ctx.request arm produced the false signed-out
read twice independently before the pattern was fixed.

## Decision
**Adopt the in-page fetch as the standard for authenticated assertions in browser drivers.**
L-037 stays the recorded rule; its status moves `candidate → validated` on this experiment
(the two divergent reads are a passing, reproducible check of the mechanism).

## Rollback
None needed (test-only pattern). The evidence lives in this file and the drivers' `accountIndex`
helpers.
