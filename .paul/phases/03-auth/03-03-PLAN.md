## Facts (measured 2026-11-24)
- `log_panel.js` polls `/api/logs?brief=1` every 5 s for every visitor and `?since=` every 1.5 s when
  open; it adds its own rail button and a status badge on load.
- The restart button (`#restart`, `restartChart`) no longer posts `/api/restart`; it reloads the
  engine locally. Spec item 25's removal is already done; the button stays (out of scope).
- `/auth/me`: local `{"auth": false}`; hosted signed out `{"auth": true, "user": null, "client_id"}`;
  signed in adds `user` and `admin` (03-02, D-017).
- Writes from the page are same-origin `fetch` with `Content-Type: application/json`, so the browser
  sends `Origin` itself; no token is involved (D-010).
- The browser check runs `hub-server --features test-idp` with `AUTH_ENABLED=true`,
  `PUBLIC_ORIGIN=http://127.0.0.1:<port>` (test-idp builds accept it), a pgsqlite database file in a
  temp directory, `GOOGLE_*_URL` pointing at `/__test-idp/*`, and the GIS script request intercepted
  and answered with a stub that calls the page's callback with a `/__test-idp/mint` token. No real
  Google request. `__Host-` cookies need `Secure`: Chromium treats `http://127.0.0.1` as a secure
  context for cookies; if the check shows the cookie refused, the fallback is recorded as a fact (not
  silently a non-`__Host-` name).
- `modern-web-guidance` was denied by the auto-mode classifier on 2026-11-24 (as in 01-03, DEBT-004).

## Decisions applied
- Written defaults: the menu is a button plus menu pattern (WAI-ARIA menu button), keyboard parity,
  Escape closes and returns focus; delete account uses a modal dialog with a typed-free confirm button
  in the destructive token (`action.destructive`), never the primary colour; One Tap respects a
  `sessionStorage` dismissal flag per tab; `sign-in failed` (`?signin=failed`) shows the mockup's
  inline message and strips the query with `history.replaceState`.
- Out of scope with reason: sync status (Phase 05) and MT5 bridges (Phase 07) menu entries (D-013);
  the log panel's per-feed health and TTFC line (spec item 26, Phase 04 with the beacon), so
  `/dashboard-design` known-totals do not apply to this plan (the panel's content is unchanged);
  `--onAccent` in `theme.js` (item 27) is taken only if a contrast gate on the new controls needs it.

<acceptance_criteria>

## AC-1: The control matches the mockup in every state
```gherkin
Given hub.html served by a test-idp hub-server
When the page loads in local mode, hosted signed out, signing in, sign-in failed, signed in, and as an admin
Then local mode renders no sign-in control; the other states match mockup 01 frame by frame (position, label, avatar, menu items)
And the menu opens by click, Enter, Space and ArrowDown, moves with the arrow keys, closes with Escape and returns focus to the trigger
And every interactive element shows default, hover, focus, active and disabled states from tokens, with no hardcoded colour, no native select and no one-sided border
```

## AC-2: Sign-in, sign-out and delete work end to end
```gherkin
Given the hosted test-idp server
When the user takes the button flow through /__test-idp/authorize
Then the page returns signed in with the avatar shown
When the One Tap stub fires
Then the sign-in request is a JSON POST {"credential"} to /auth/google/onetap, and after a dismissal the prompt does not reappear in that tab
When the user signs out
Then POST /auth/logout is 204 and the header returns to signed out
When the user deletes the account through the confirm dialog (keyboard reachable, Escape cancels, focus trapped)
Then DELETE /api/me is 204, the header shows signed out, and the busy and error states of mockup 04 appear when the server is slow or answers 503
```

## AC-3: Log polling is gated (R13, D-012)
```gherkin
Given the network log of a 15 s window
Then local mode polls /api/logs as before
And hosted signed out and a signed-in member make zero /api/logs and zero /admin/logs requests, and no log rail entry or badge is rendered
And an admin sees the log entry, polls /admin/logs, and the journal POST answers 200
```

## AC-4: Render and look, accessibility
```gherkin
Given each changed screen state in light and dark, at 320 px and desktop width
When polish.py shot and design_lint.py check run
Then red lint findings are 0 and the three worst problems per screen are fixed and logged in polish-log.md
And the kit's state-aware contrast and axe gates pass on the header and dialog, run with DS_REQUIRE_BROWSER=1, and the real N/N line is quoted
```

## AC-5: The checks can fail
```gherkin
Given the browser checks green
When the log panel is made to poll unconditionally, the admin entry is hidden for admins, the One Tap POST is made form-encoded, and the delete runs without the confirm, one at a time
Then each makes its check FAIL, and restoring it makes the check pass again
```
