<objective>
## Goal
With `AUTH_ENABLED=true`, `AppState::start` connects and migrates, and `app(state)` serves the hosted
routes: a first Google sign-in creates one user and the second reuses it; forged tokens, a wrong
nonce, a missing or foreign `Origin`, and a reused, expired or wrong-key desktop code are refused;
every `/admin/*` answers 404 to everyone but an admin. Local mode is unchanged.

## Purpose
G4 (accounts) and the Phase 03 accept line. Everything later (sync, desktop app, MT5 bridges) keys on
the session this plan creates.

## Output
The `auth` module (service, pure rules, sealed ids, private store, Google client, test IdP), the
gate and route table, the handlers, `AppState::start`, and the `auth`, `admin` and `gate` suites.
</objective>

## Facts (measured)
- From 03-01: the engine harness, `Db`, `is_unique_violation`, both measured numbers (start-up per
  test; concurrent writers). If 03-01 recorded that a second concurrent writer fails, its SQLSTATE and
  message are what the sign-in effect treats as retryable.
- D-014 statement rule and the grounding probe tables apply to every statement in `store.rs`.
- Routes today: `/api/logs` GET and `/api/logs/journal` POST in `app()` (`lib.rs`); the fallback
  answers JSON 404 only under `/api/`.
- No Postgres server on this PC: Postgres cases run in CI (03-01 job, extended here with the feature).

## Decisions applied
- D-010 (Origin + SameSite, no token), D-012 (logs), D-015 (any exchange attempt burns the code),
  D-016 (health unchanged), D-017 (`client_id` on `/auth/me`). Architecture defaults recorded as plan
  facts: a database outage answers 503 `service unavailable` (also on `/admin/*`), never a faked
  signed-out; the limiter covers `/auth/*` and `/admin/*`; RSA test keys are generated per test binary
  (`OnceLock`), never committed; `/__test-idp/*` exists only with the feature and only in hosted mode.
- **Control removed, stated loudly:** `post_guard` allows a missing `Origin` (Python parity, local
  tools). In hosted mode the gate replaces it on `/api/me*`, `/auth/*`, `/admin/*` with the stricter
  rule (missing refused). In local mode nothing changes. `/api/logs*` (and its lenient guard) is
  removed from hosted mode entirely (404), compensated by the admin-only `/admin/logs*` behind the gate.

## AC-1: Tokens are verified exactly (pure tables)
```gherkin
Given verify_id_token with a test key set and Expect { client_id, issuers, nonce }
When the token has wrong aud, wrong iss, exp == now, a bad signature, alg HS256, alg none, no sub, no email, or a nonce mismatch
Then each returns its Refusal variant (WrongAudience, WrongIssuer, Expired, BadSignature, AlgNotRs256, AlgNotRs256, MissingClaim("sub"), MissingClaim("email"), NonceMismatch)
And a valid token gives a VerifiedIdentity with email_verified copied
And jwks_ttl clamps max-age=10 to 300 s and max-age=999999 to 86400 s, absent to 300 s
And jwks_needs_fetch refetches an unknown kid at 61 s after the last fetch but not at 59 s
And session_check gives Valid at last_seen + 24 h - 1 s, Slide at + 24 h + 1 s, Expired at expires_at
And OauthTicket::open refuses a flipped MAC byte (TicketBadMac) and exp + 1 (TicketExpired)
```

## AC-2: Sign-in creates one user, on both engines
```gherkin
Given a hosted app over the TestIdp and a ManualClock
When POST /auth/google/onetap with a valid credential and Origin = PUBLIC_ORIGIN
Then 200 {"user": {...}, "admin": false} and Set-Cookie __Host-vtv_session=<43 chars>; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=2592000
And sessions.id_hash equals SHA-256 of the cookie value, and no row holds the raw value
And a second sign-in for the same sub reuses the user (users count 1) and updates name and last_login_at
And two concurrent first sign-ins for one sub (pool of 4) both answer 200 with one user and one identity
And a forged credential (each AC-1 case end to end) answers 401 {"error":"sign-in failed"} and creates no row
```

## AC-3: The web button flow and the oauth cookie
```gherkin
Given GET /auth/google/start?client=web
Then 302 to the configured authorization URL with state, nonce, code_challenge_method=S256 and a challenge equal to S256(verifier),
  and Set-Cookie __Host-vtv_oauth (HttpOnly, Secure, SameSite=Lax, Path=/, Max-Age=600)
When GET /auth/google/callback with the matching state and the TestIdp's code
Then 302 to /hub.html with the session cookie set and the oauth cookie cleared, and the TestIdp saw the verifier
And a tampered cookie, a callback after 601 s, a wrong state, an absent cookie, a wrong nonce in the returned token, and error=access_denied
  each land on 302 /hub.html?signin=failed with the oauth cookie cleared and no session row
```

## AC-4: Desktop codes are one-time and bound to the key (D-015)
```gherkin
Given start with client=desktop&dk=K (22..128 of [A-Za-z0-9_-]; a bad dk is 400 bad request)
When the callback completes
Then 302 to vtradingview://auth?code=C, and the placeholder session is unusable (no response carries its id, expires in 60 s)
When POST /auth/desktop/exchange {"code": C, "desktop_key": K}
Then 200 with a fresh session cookie, the placeholder row gone, a second exchange 401
And an exchange at +61 s is 401; a wrong key is 401 and the right key afterwards is also 401 (burned);
  two concurrent exchanges give exactly one 200
```

## AC-5: The gate (D-010) and the admin 404, table driven
```gherkin
Given route_specs(state) for the hosted app
When every non-GET route is sent with no Origin, with Origin https://evil.example, and with PUBLIC_ORIGIN
Then the first two answer 403 {"error":"forbidden origin"} and the third reaches the handler
And a text/plain body is 415 and a 300,001-byte body is 413; GET /auth/me needs no Origin
And every hosted route lies in an area (/auth/, /admin/, /api/me exactly or /api/me/), and /api/metrics would not
And every /admin/* route answers 404 {"error":"not found"} signed out, as a member, as an ADMIN_EMAILS address with email_verified=false,
  and to an admin with a foreign Origin on a non-GET; an admin gets the Phase 1 logs body and the journal 200
```

## AC-6: Sessions slide, end, and delete cascades
```gherkin
Given a signed-in member
When /auth/me is called at +23 h, +24 h 1 s, and after 30 days 1 s idle
Then no Set-Cookie and an unchanged row at +23 h; exactly one Set-Cookie and a moved row at +24 h 1 s; signed out (user null) after 30 days idle
And POST /auth/logout is 204 with Max-Age=0 and the row gone; a second logout is 204
And DELETE /api/me is 204, every table holds 0 rows for that user, and the old cookie reads as signed out
And sweep_expired removes expired sessions (and their codes by cascade)
```
