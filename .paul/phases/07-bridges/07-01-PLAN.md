<objective>
## Goal
The bridge foundation exists and is proven without any route wiring: migration `0003_mt5_bridges`, the
single-table store, XChaCha20-Poly1305 token sealing under `VTV_SECRET_KEY`, the SSRF guard that refuses
every private target (loopback allowed only when auth is off, D-001), and `BridgeClient` with pinned
address connects, exact-error causes, and the spec's limits (10 s, 5 MB, no redirects, 2 concurrent).

## Purpose
G6 ("own broker data, safely") is the phase's hard guardrail: the server calls user-supplied URLs, so
the guard and the client are the attack surface. 07-03 wires routes onto this core; 07-04 renders it.
Building the core first, in isolation, lets the refusal tables and the crypto be mutation-proved before
any endpoint exists to hide behind.

## Output
`crates/hub-core/src/bridges/` (mod, guard, crypto, client, store), migration 0003, the
`chacha20poly1305` workspace dependency, and green unit suites on both database engines.
</objective>

## AC-2: Tokens are sealed at rest and never leak
```gherkin
Given a bridge token and the hub SecretKey
When seal() then open() runs
Then the token round-trips; a tampered ciphertext or nonce fails open(); a different SecretKey fails
     open(); the stored blob is nonce || ciphertext with no plaintext bytes; Debug of any bridges type
     never prints the token
```

## AC-3: The guard refuses every private target and honours the D-001 exception
```gherkin
Given vet_url(raw, auth_enabled)
When the URL is https with no user info on port 443 or 1024..=65535 and every resolved address is public
Then vet_url yields Vetted
When the URL is http, carries user info, sits on a banned port, or any resolved address is loopback
     (127.0.0.0/8, ::1), RFC 1918 (10/8, 172.16/12, 192.168/16), CGNAT (100.64/10), link-local v4
     (169.254/16, including 169.254.169.254), link-local v6 (fe80::/10), unique-local (fc00::/7),
     multicast, unspecified, or the IPv4-mapped form of any of these
Then vet_url refuses with the specific reason; with auth_enabled=false loopback is allowed and every
     other refused class stays refused (D-001)
```

## AC-4: The client calls the vetted address only, with the spec's limits
```gherkin
Given a vetted bridge URL whose host resolves twice (second answer private)
When BridgeClient calls it
Then it connects only to the vetted addresses (the pinned-resolver test); a 302 to any target is not
     followed; a response larger than 5 MB is refused with TooLarge; a call slower than 10 s times out
     (wait() allows 25 s); a third concurrent call to the same bridge waits for a permit; the error
     enum carries exactly Refused/Dns/Cert/Auth/Timeout/TooLarge/Bridge
```

## AC-5: The refusal table is mutation-proved
```gherkin
Given mutation m1: one refused range (CGNAT) removed from refused_reason
When the range table test runs
Then it fails while m1 is applied (grepped as landed first, L-009) and passes after restore; the exit
     status of every judged command is quoted bare (L-023)
```
