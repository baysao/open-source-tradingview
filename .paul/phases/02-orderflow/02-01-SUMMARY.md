## Deviations (each verified)

1. **The lower-bar cache rules moved into 02-01.** `rows_need`, `rows_merge` and `rows_window` are
   pure functions in `calc.rs`, because the warm-cache golden cases need Python's planning and
   insertion order. 02-02 wraps them in the locked `RowsCache`. Interfaces otherwise as planned.
2. **`FootprintArgs`.** clippy's `too_many_arguments` grouped `tf`, range, `row_size` and `fill`
   into one struct; `footprint(&args, data, now_s, &resolved)`.
3. **`nice_step` ints stop at k = 17.** Python ints are unbounded; i64 holds 10 x 10^17. Row sizes
   that large do not occur for prices; the table covers k up to 15.
4. **REST segments come from the daily archive.** Binance `aggTrades` answers `-4166 Search window
   is restricted to recent 2 days only` for both `startTime` and `fromId` older than two days. The
   segments for D+1 are REST-format rows (`a`, `p`, `q`, `T`, `m`) built from the D+1 daily CSV, which
   carries the same fields, with price and quantity strings kept byte for byte.
5. **`profile_rows_zero` window.** The first window (08:00 to 09:00) snaps to the next whole session
   (13:00), loads nothing, and Python answers 200 with no sessions. The case now starts at 07:00 and
   reaches Python's `ZeroDivisionError`.
6. **Two cases added.** `footprint_btc_m1_tick_rows` (row size 0.1, fill 0), because no earlier
   fixture had an empty footprint row, so the int-0 kind was never compared. `warm_cache_m15_order`
   (the first delta starts mid-candle), so one M15 candle takes minutes from two fetches.
7. **Reply structs are `Serialize` only.** The golden suite and the contract suite compare raw JSON,
   so `Deserialize` and `deny_unknown_fields` add nothing yet.
8. **A stale test build.** The mutation script restored files with an older mtime, and cargo skipped
   the rebuild, so one clean run used the mutated binary and reported a false difference. The script
   now touches each restored file; the clean run is 25/0/0 again (L-013).
9. **Lint scoping.** `#![allow(clippy::disallowed_methods)]` in `hub-core/src/lib.rs` (Phase 01 code
   keeps `f64::max` where it already matches Python) and in the golden test (comparator arithmetic);
   `#![deny]` in `orderflow/mod.rs`.
