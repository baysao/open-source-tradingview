<objective>
## Goal
`hub_core::orderflow::calc` computes delta, session volume profile and footprint from loaded inputs,
and every captured fixture case gives the same JSON as Python, bit for bit and number kind for number
kind, with no network in any test.

## Purpose
G1 parity for order flow, and the base the 02-02 loaders and 02-03 routes call. Doing the arithmetic
first, alone, means a later mismatch can only be a loader or route bug.

## Output
The pure half of the order-flow module, its reply types, the capture script, the fixture tree
(including the store scenario inputs 02-02 replays) and the golden test.
</objective>

## Facts (measured 2026-11-23)
- Python 3.12.10, numpy 2.5.0, pandas 3.0.6 on this machine. `sum([1e16, 1.0, -1e16])` is `1.0`
  (Neumaier); a left fold gives `0.0`.
- `orderflow_api.py`: `round(x, 6)` on delta fields, `round(x, 4)` on profile `buy`/`sell`/`total`/
  `delta` and footprint cells, `round(x, 6)` on developing levels; `lo`, `step`, `poc`, `vah`, `val`
  unrounded; empty footprint rows `round(0, 4)` is int `0` (line 432); `nice_step` int for k >= 0.
- Dict insertion order reaches a float sum only in the footprint fill (lines 417, 426); delta
  (line 195), profile (line 315) and `_shift` (lines 155, 165) sort first.
- `sources/binance.rs:41` maps gold to `PAXGUSDT`; order flow must read the raw ticker (`XAUUSDT`).
- No `hub/.cache` exists; the workspace already has `indexmap`, `lru`, `futures-util`; `zip` is new.
