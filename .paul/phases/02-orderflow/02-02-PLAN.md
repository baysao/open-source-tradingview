<objective>
## Goal
`OrderFlow::answer(&Ask)` loads what each computation needs (futures list, klines, chart history,
trades) and returns the same JSON as Python for every 02-01 fixture case, through the real shell
against local fakes; the trade store's `trades()` window equals Python's `TradeStore.trades` on every
recorded scenario.

## Purpose
The order-flow routes (02-03) need a service that respects Binance's limits, keeps every trade the
charts asked for, and survives restarts through the hour cache, with the same coverage rules Python
has.

## Output
`binance.rs` (transport, budget, futures list), `trades.rs` (store, caches, archive), the `OrderFlow`
service and `Ask::parse` in `mod.rs`, `WallClock`, the new `Endpoints` and config fields, and two test
suites.
</objective>

## Facts (measured 2026-11-23)
- Constants (spec R10): budget 1900/min of 2400; Background leaves 400; `X-MBX-USED-WEIGHT-1M` caps
  1800 (Background) and 2200 (Chart); 429/418 stop all calls for `Retry-After` or 60 s; wait clamped
  0.2 to 5 s; klines 1500 per page; aggTrades 1000 per page; `MAX_PAST_DAYS = 2`; `MAX_REST_HOURS =
  30`; `POLL_S = 4.0`; `IDLE_STOP_S = 600`; save every 60 s; evict older than 32 h; failed day retried
  after 30 min; hour files older than 33 h deleted at load.
- Python init order (L-011): the futures set is empty until the first request fetches it; a store is
  created and its hour files loaded on its first `trades()`; the loops start only when a request
  reaches the REST range; a day download starts only when a request reaches that day.
- `_poll_head`: fresh head when `t_req - head.t1 < 120 s` (`t_req = now - 1000 ms`), then
  `fromId = last + 1`, else the newest page; `more` when a fresh page is full.
- `BarsCache` pages with `to_ms` are cached 10 minutes; history calls whose page reaches the forming
  bar must use `Freshness::Fresh`.
- `tests/ws_e2e.rs` builds `Endpoints { .. }` as a full literal and must gain `..Endpoints::default()`.

## Decisions applied

`zip` at a version compatible with the toolchain, `default-features = false, features = ["deflate"]`).

## AC-1: The weight budget and futures list follow Python
```gherkin
Given WeightState under tokio's paused clock and a local fake fapi
When calls of weight 10 and 20 are taken at Chart and Background priority
Then Chart stops at 1900 and Background at 1500 within 60 s, a reply header of 1800 stops Background
and 2200 stops Chart, a 429 with Retry-After 7 blocks both priorities for 7 s (60 s without the
header), and no std Mutex is held across an await; FuturesList fetches once for eight concurrent
callers, refreshes after 6 h, and after a failure keeps the old set and retries after 5 minutes
```

## AC-2: The trade store equals Python's
```gherkin
Given each 02-01 store scenario (segments from the recorded aggTrades pages, day files from the
sliced zips, busy and failed days, floor)
When `assemble` runs for each recorded call with its frozen now
Then trades (same values, same order), covered, pending and the effects equal Python's recorded
window and after-state; Segments::add of the same chunks in random order and repeated gives the same
segments; a trade inside a day file's range is never counted twice
```

## AC-3: Store lifecycle and caches
```gherkin
Given a store under the paused clock with a fake fapi and a temp cache dir
When a window reaches the REST range, time advances, and requests stop
Then the head loop polls every 4 s and is never delayed by back-fill, complete hours are saved every
60 s as .bin files (written to .part and renamed) and reloaded by a new store, data older than 32 h is
evicted, the loops stop after 600 s idle with a final save, a request during the idle exit starts them
again, a failed day is retried after 30 minutes, and dropping the OrderFlow stops every loop
```

## AC-4: The service equals Python on every fixture
```gherkin
Given every 02-01 case, a fake fapi serving its recorded klines and exchangeInfo, a strict
ReplayHistory behind BarsCache (an unrecorded call panics), the store seeded from the case's window,
and WallClock::frozen at the case's now
When `OrderFlow::answer(&Ask::parse(kind, &query, now))` runs
Then the reply equals the case's expected JSON with assert_same, the history calls equal the recorded
calls, and Ask::parse gives Python's defaults and error texts for the parse cases
```
