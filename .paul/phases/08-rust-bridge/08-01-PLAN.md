<objective>
## Goal
A compiling `crates/mt5-bridge` crate whose MCP client (mcp.rs) and domain core (term.rs) pass
their in-crate suites: session lifecycle, reopen-once, SSE scan, the five tools' response parsing,
bar/offset/tick math, and the resync loop under a shrunken SyncPolicy.

## Purpose
mcp.rs is the parity-critical, highest-risk code of the whole phase. Building and unit-testing it
first, in isolation, means the HTTP layer in 08-02 never debug-guesses at terminal behavior. The
domain core carries the exact Python arithmetic (offset rounding, tick ms slicing, bar keys) that
the 08-03 contract suite will diff byte for byte.

## Output
crates/mt5-bridge (Cargo.toml, src/main.rs, src/mcp.rs, src/term.rs) compiling in the root
workspace, `cargo test -p mt5-bridge` green, workspace `cargo test --workspace` still green and
tauri-free.
</objective>

## AC-1: The crate exists as a root workspace member with pinned deps
Given the root Cargo workspace
When `cargo metadata` (or any build) resolves
Then `crates/mt5-bridge` is a member; its deps are workspace-pinned only (axum 0.8, tokio,
reqwest 0.12 rustls, serde/serde_json float_roundtrip, chrono) plus crate-scoped `subtle` and
`dotenvy`; no new transitive major lands in Cargo.lock without the plan naming it.

## AC-2: MCP session lifecycle matches the oracle
Given the in-crate fake terminal (tokio TcpListener, 07-03 Fake pattern)
When the client initializes and calls a tool
Then the first request is `initialize` with protocolVersion "2025-06-18" and clientInfo name
"chart-bridge", followed by `notifications/initialized`; the `Mcp-Session-Id` response header is
captured and sent on every later call; every request carries `Authorization: Bearer <token>` and
Accept "application/json, text/event-stream".

## AC-3: Reopen-once and error parity
Given a fake that drops the session mid-call (transport error or HTTP error on the first attempt)
When `call` runs
Then the client reopens (initialize count increments by exactly 1) and retries once, succeeding on
the second attempt; a fake answering `isError: true` makes `call` return an error carrying the
content text verbatim.

## AC-4: SSE-shaped and plain responses parse identically
Given fakes answering (a) a bare JSON body and (b) an SSE body whose last `data:` line holds the JSON
When `call` runs
Then both parse to the same Value (the Python scan keeps the last data: line).

## AC-5: Domain arithmetic matches Python exactly
Given the measured Python rules
When term.rs functions run
Then: bar_key joins "time,close,high,low,volume" with float formatting equal to Python str();
offset rounding is to 30-minute steps with the |d-h| >= 90 refusal; tick ms parses time_ms chars
20..23 with absent = 0; Tf parses exactly M1..D1 and rejects M2 with the Python error text
`unknown timeframe M2`; bars() under a shrunken SyncPolicy (cap 200 ms, step 10 ms) trims to
limit, clamps limit at 5000, and triples the span while short.

</acceptance_criteria>
