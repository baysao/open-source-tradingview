<objective>
## Goal
Make the signed-out sign-in control work inside the desktop window: it calls the one desktop command
instead of navigating, shows the mockup-06 waiting overlay (waiting / Try again / Cancel / failed),
consumes the `vtv:desktop-code` event, POSTs `/auth/desktop/exchange`, and maps each server refusal to
copy that says what to do — while the browser path stays byte-for-byte the behaviour it has today.

## Purpose
This is where the phase becomes visible to a user. Three things can go wrong and all three are silent:

1. **The browser path regresses.** `hub/auth.js` serves both the hosted site and the desktop window, so a
   careless branch turns the normal web sign-in into a broken button for every visitor. The browser path
   must be provably unchanged (AC-1), not "still looks fine".
2. **The overlay lies.** The mockup's four states exist because the flow spans two applications; a
   spinner forever is the worst outcome and the most likely one (the code expires in 60 s and nobody
   tells the user).
3. **The refusal is mis-explained.** `auth_error` (`crates/hub-core/src/routes/auth.rs:175`) returns 401
   `sign-in failed` for a reused or expired code and 400 `bad request` for a malformed body. Telling a
   user "sign-in failed" when the link simply expired sends them to support instead of to Try again.

The design track's screen 06 (`06-desktop-signin-waiting.html`) is the normative layout; this plan
implements it, with the `DESIGN-STATE` D4 tokens already in `hub.html`.

## Output
- `hub/auth.js` — the desktop branch, isolated in one function so the web path is untouched
- `hub/hub.html` — the overlay's styles, as tokens (no hardcoded values; `lint_hardcodes` gates it)
- `.paul/runs/check-0603.mjs` + `.sh` — the driver: five overlay states, the exchange call, the refusal copy
- `.paul/ds-receipts/current/` — a refreshed 8/8 receipt set for `hub.html` (the page changed)
</objective>

## Interfaces

The page code may use exactly this (from 06-01 and 06-02):

```js
window.vtvDesktop.startSignIn(): Promise<string>        // -> desktop_key, 43 chars
window.addEventListener("vtv:desktop-code", (e) => e.detail.code)   // CustomEvent
POST /auth/desktop/exchange  {"code": "...", "desktop_key": "..."}  // -> 200 | 401 | 400 | 503
```

Detection is `typeof window.vtvDesktop?.startSignIn === "function"` — never `window.__TAURI__`, which
06-01 deliberately does not publish (D-029's capability-minimisation).

**One decision recorded here because the plan makes it, not the user:** the overlay is rendered into the
existing header slot area as a fixed-position card (mockup 06's `.over`), not as a new route or a
separate page. Rationale: the window has no chrome to speak of and the user must still see the charts
behind it; a separate page would lose the app's context and would need its own gate receipts.

```gherkin

Then its container has role="status" and aria-busy="true", and the text names what is happening

Then the failed state shows the expired copy (not an endless spinner)
```

```gherkin
Given the exchange replies
When the status is 401 "sign-in failed" then the copy says the link expired or was already used
When the status is 400 "bad request" then the copy says to try again from the app
When the status is 503 "service unavailable" then the copy says the server is unavailable right now
When the fetch itself throws then the copy says the connection failed and to check it
And every case keeps the user signed out and the charts untouched
```

<task type="auto">
  <name>Task 2: The waiting overlay, four states</name>
  <depends>Task 1</depends>
  <files>hub/auth.js, hub/hub.html</files>
  <guides>accessibility, accessible-error-announcement</guides>
  <action>
    **Load `/design-doctrine`, `/design-component`, `/design-code` first; then build the overlay from
    `06-desktop-signin-waiting.html`, not from memory.**

    Structure (one card, one container, states swapped inside it):

    ```html
    <div class="desk-over" hidden>
      <div class="desk-card" role="status" aria-live="polite" aria-busy="true">
        <!-- head: spinner or alert icon + h3 + p -->
        <!-- acts: Try again (button), Cancel (button) -->
      </div>
    </div>
    ```

    State rules from the guides:
    - **waiting**: `role="status"`, `aria-live="polite"`, `aria-busy="true"`; the text names the place
      ("Waiting for Google in your browser") so the message is useful read alone out of context
      (`accessibility`: a status region's text must stand on its own).
    - **failed**: switch to `role="alert"` (implicit `aria-live="assertive"`) and clear `aria-busy`
      (`accessible-error-announcement`: announce the error when it exists, and synchronise the visual and
      programmatic state — `aria-busy` must not stay `true` over a finished state).
    - **leaving**: remove the node rather than hiding it, so nothing stale stays in the accessibility tree.
    - Focus: on show, move focus to the card's heading (or the Try again button in the failed state); on
      leave, return focus to the sign-in button. The window has no other focusable chrome, so losing focus
      to `document.body` is a real keyboard dead end.

    Styles go in `hub/hub.html`'s existing `<style>` block, tokens only — mirror the mockup's `.over` /
    `.card` rules but map every value to a token from the block at `hub/hub.html:11-40`. If a needed value
    has no token, add a named token to that block (the 05-04 pattern: "a value with no scale entry lives
    here as a named token, nowhere else") and say so in the SUMMARY. `lint_hardcodes` and
    `validate_tokens` must both stay green.

    Behaviours:
    - **60 s timeout**: `setTimeout` at 60 s (the code's server-side life) → failed state with the expired
      copy. Clear the timer in every exit path.
    - **Cancel**: clear the timer, remove the overlay, restore the button, call `start_sign_in`? **No** —
      cancel must not start anything; it returns to the signed-out button and the key is simply abandoned
      server-side (it expires with the code).
    - **Try again**: clear the timer, `await window.vtvDesktop.startSignIn()` (06-01 rotates the key after a
      delivery), back to waiting, new timer.
    - Reduced motion: the spinner is the mockup's; if `prefers-reduced-motion` is set, no pulse. The hub
      already has a `--spin` convention — reuse it rather than inventing a second one.

    Do not add a `<dialog>`: the overlay is not a modal choice, and the user must be able to see the charts
    behind it (mockup 06's `.over` is an overlay, not a dialog).
  </action>

<task type="auto">
  <name>Task 3: The exchange and the refusal copy</name>
  <depends>Task 2</depends>
  <files>hub/auth.js</files>
  <action>
    Listen once, at module scope (not inside the render function, or every re-render adds a listener):

    ```js
    window.addEventListener("vtv:desktop-code", (e) => {
      const code = e.detail && e.detail.code;
      if (!code || !desktopKey) return;      // a code with no key is unusable; let the timer expire
      exchange(code);
    });
    ```

    `exchange(code)`:
    ```js
    const r = await fetch("/auth/desktop/exchange", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ code, desktop_key: desktopKey }),
    });
    ```
    - `r.status === 200` → `desktopKey = ""` (the code is burned; do not keep a spent key), remove the
      overlay, `await reload()`.
    - `401` → failed with: "Error: the link from the browser expired or was already used. Choose Try again
      and finish signing in once." (the server's own wording for that branch is the 401 `sign-in failed`,
      `crates/hub-core/src/routes/auth.rs:177`).
    - `400` → failed with: "Error: the app sent a malformed request. Choose Try again."
    - `503` → failed with: "Error: the server is not available right now. Your charts are unchanged."
    - a thrown fetch → failed with: "Error: the server did not answer. Check your connection, then choose
      Try again."
    - Every case sets `desktopKey = ""` before offering Try again, so a stale key cannot be reused with
      the old code.

    Copy discipline, matching the existing dialog's tone (`hub/auth.js:361-365`): start with "Error:",
    say what happened, say what the data's state is ("Your charts are unchanged"), then what to do. Use
    `--text` for the message with a `--bad` icon, never `--bad` text — the taste record measured
    `bad`-on-panel at 4.02 (below AA) and the fix is text colour + icon
    (`.paul/design/specs/vtradingview.md`, the contrast table).

    Do **not** retry automatically: a burned code makes a retry a guaranteed 401, and a silent retry loop
    would look like a hang.
  </action>
