## Gotchas that live nowhere else (fresh, from the live run)

1. **The permission id is `allow-start-sign-in`, not `allow-start_sign_in`.** tauri-build slugifies
   (`command.replace('_', "-")`, `tauri-utils-2.10.4/src/acl/build.rs:331`). 06-02 must not re-introduce
   the underscore anywhere.
2. **`window::build(app)` takes no state now.** `DesktopState` is `app.manage()`d in `setup`, because a
   `State<'_, T>` command parameter only resolves against the managed store. 06-02 reads it with
   `app.state::<crate::state::DesktopState>()`. Do not thread it through the builder again.
3. **`start_sign_in` returns in 0.00 s by launching the browser on a worker thread.** A synchronous
   `tauri_plugin_opener::open_url` on a Tauri command runs on the main thread and blocked the whole app
   for 84 s (`os error 1223`, ERROR_CANCELLED) before failing. Nothing downstream may assume the browser
   tab already exists.
4. **`tauri::include_image!` resolves relative to the crate root**, not `src/` — hence
   `include_image!("icons/32x32.png")`. `Image::from_bytes` is feature-gated and absent here.
5. **Live round trip is blocked by DEBT-013, not by phase 06.** Google answers
   `Error 400: redirect_uri_mismatch`; probed: `/auth/google/start?client=desktop&dk=…` 302s with
   `redirect_uri=https%3A%2F%2Fvtradingview.com%2Fauth%2Fgoogle%2Fcallback`, which the OAuth client does
   not allow. Same failure on the web path. 06-04's human-verify step 4 cannot pass until the owner
   registers the URI; the desktop work is otherwise provably correct up to Google's page.
6. **WebView2 holds the user-data dir after a timed-out run.** A relaunch then panics with
   `HRESULT(0x800700AA) "The requested resource is in use"`. Kill `msedgewebview2.exe` before relaunching.
7. **Driving the window from a script:** launch with
   `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=922N"`, then `Runtime.evaluate` over
   the target's websocket. `python -m pip install websocket-client` was needed once on this box.
8. **The live site serves a pre-phase-05 `auth.js`** (352 lines vs the repo's 396). It has no sync line
   and its Google Identity Services auto-navigates the window to Google — which the guard correctly
   refuses and hands to the browser. 06-03's `if (!isDesktop()) loadGis(...)` is what stops that, so the
   desktop branch must not depend on the deployed page already having it.
